# 콜드 스타트와 Scale-to-Zero

엔드포인트의 `min_replica` 기본값은 `0` 입니다. 즉 아무도 호출하지 않는 엔드포인트는
파드가 0개까지 줄어들어 GPU 를 붙잡고 있지 않습니다. 이 절약이 Scale-to-Zero 이고, 그
대가로 첫 요청은 파드가 다시 뜨는 시간만큼 느려집니다. 이 페이지는 그 지연이 왜
생기는지, 그리고 애플리케이션에서 어떻게 다뤄야 하는지를 다룹니다.

## 무슨 일이 일어나는가

트래픽이 끊긴 지 `scale_down_delay` 만큼 지나면 레플리카가 `min_replica` 로 줄어듭니다.
`min_replica` 가 `0` 이면 파드가 완전히 내려갑니다. 이 상태에서 요청이 들어오면 KEDA
HTTP 인터셉터가 그 요청을 붙잡아 두고 파드를 새로 띄웁니다. 파드가 컨테이너 이미지를
당기고, 모델 가중치를 로드하고, vLLM 서버가 준비 상태가 될 때까지 원래 요청은 응답을
받지 못한 채 대기합니다. 이 전체 과정이 끝나야 응답이 옵니다 — 그래서 콜드 스타트 이후의
**첫 요청**만 유독 느리고, 그 뒤로 이어지는 요청은 이미 떠 있는 파드가 바로 처리하므로
빠릅니다.

지연 시간은 모델 크기와 이미지 크기에 따라 다릅니다. 작은 모델은 수십 초 안에 끝나기도
하고, 큰 모델은 몇 분까지 걸릴 수 있습니다. 정확한 값은 모델·클러스터마다 다르므로, 내
엔드포인트에서 실제로 재 보는 것이 가장 정확합니다.

## min_replica 를 1로 올리는 선택

콜드 스타트 지연을 아예 없애고 싶다면 `min_replica` 를 `1` 이상으로 올립니다. 그러면
트래픽이 없어도 파드가 최소 한 개는 항상 떠 있어서 모든 요청이 콜드 스타트 없이
처리됩니다.

대가는 **비용**입니다. 파드가 늘 떠 있다는 것은 GPU/CPU 자원을 계속 점유한다는 뜻이고,
트래픽이 거의 없는 엔드포인트라도 그 자원만큼 계속 과금됩니다. 이 트레이드오프는
용도에 따라 다르게 판단하면 됩니다.

| 상황 | 권장 |
|---|---|
| 사람이 직접 쓰는 프로덕션 서비스, 지연에 민감 | `min_replica: 1` 이상 |
| 내부 배치·야간 작업처럼 가끔만 호출 | `min_replica: 0` (기본값) |
| 트래픽이 몰리는 시간대가 예측 가능 | 그 시간대만 `min_replica` 를 올렸다가 되돌리기 |

## scaling_timings 튜닝

`scale_up_delay` 와 `scale_down_delay` 는 초 단위로 조정할 수 있습니다.

```json
{
  "scaling_timings": {
    "scale_up_delay": 0,
    "scale_down_delay": 300
  }
}
```

`scale_down_delay` 를 늘리면 트래픽이 뜸해도 파드가 더 오래 살아 있어 다음 요청이 콜드
스타트를 덜 겪습니다 — 대신 그만큼 유휴 시간에도 자원을 점유합니다. 반대로 줄이면 비용은
아끼지만 콜드 스타트를 더 자주 겪습니다. 트래픽 패턴에 맞춰 조정하는 값이지, 정답이
정해져 있는 값은 아닙니다.

## 클라이언트 타임아웃을 넉넉히 잡는다

애플리케이션의 HTTP 클라이언트가 기본 타임아웃(보통 몇 초에서 30초 안팎)을 쓰고
있다면, 콜드 스타트 중인 엔드포인트를 호출했을 때 응답이 오기 전에 클라이언트가 먼저
포기하고 타임아웃 에러를 낼 수 있습니다. 콜드 스타트를 겪을 가능성이 있는 엔드포인트를
호출한다면 타임아웃을 모델 로딩 시간을 감안해 넉넉히(수 분 단위로) 잡으세요.

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://<your-endpoint-host>/v1",
    api_key="not-used",
    timeout=180.0,  # 콜드 스타트를 감안한 넉넉한 타임아웃
)
```

타임아웃으로 실패한 요청을 재시도하는 전략은 [에러 처리](/guide/inference/errors) 의
504·타임아웃 절을 참고하세요.

## 미리 깨워 두기 (wake)

사용자가 곧 요청을 보낼 것으로 예상되는 시점(예: 채팅 화면 진입, 특정 페이지 로드)에
가벼운 요청을 미리 한 번 보내 두면, 실제 요청이 오기 전에 파드를 깨워 둘 수 있습니다.
`/v1/models` 처럼 모델을 로드해야만 응답할 수 있는 가벼운 경로를 호출하는 방식이 흔히
쓰입니다.

```bash
# 실제 추론 요청 전에 미리 한 번 호출해 파드를 깨워 둔다
curl https://<your-endpoint-host>/v1/models
```

이 방식은 콜드 스타트 자체를 없애지는 못하지만, 지연을 사용자가 실제로 기다리는
시점에서 그 앞 시점으로 옮길 수 있습니다.
