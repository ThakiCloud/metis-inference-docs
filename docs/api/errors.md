# 에러 코드

플랫폼 API 는 실패를 일관된 모양으로 돌려줍니다.

```json
{
  "error": "INVALID_INPUT",
  "message": "Invalid request parameters",
  "request_id": "req_abc123xyz",
  "timestamp": 1701676800
}
```

| 필드 | 설명 |
|---|---|
| `error` | 기계가 분기할 코드. 문자열 상수입니다. |
| `message` | 사람이 읽을 설명. 문구는 바뀔 수 있으니 여기에 조건 분기를 걸지 마세요. |
| `request_id` | 문의할 때 이 값을 함께 알려 주면 서버 로그에서 바로 찾습니다. |
| `timestamp` | Unix 초 |
| `details` | 일부 에러에만 있는 추가 정보 |

**분기는 `error` 값으로 하세요.** `message` 는 표시용입니다.

## HTTP 상태별 대응

| 상태 | 의미 | 흔한 원인 | 조치 |
|---|---|---|---|
| 400 | 요청이 잘못됨 | 필드 이름·타입 오류, 이름이 DNS-1123 위반, 필수 값 누락 | 요청 본문을 고칩니다. 재시도해도 같습니다. |
| 401 | 인증 실패 | 토큰 없음·만료·`Bearer ` 누락 | 토큰을 갱신하고 한 번만 재시도합니다. |
| 403 | 권한 없음 | 그 프로젝트 소속이 아니거나 관리자 전용 경로 | 권한을 확인합니다. 재시도해도 같습니다. |
| 404 | 없음 | ID 오타, 이미 삭제됨, 다른 프로젝트의 리소스 | ID 와 프로젝트를 확인합니다. |
| 409 | 충돌 | 이름 중복, `version` 불일치 | 다시 조회해 최신 상태로 재시도합니다. |
| 422 | 검증 실패 | 자원 부족 등 요청은 맞지만 수행할 수 없음 | 아래 `RESOURCE_VALIDATION_FAILED` 참고 |
| 429 | 한도 초과 | 레이트 리밋 | `retry_after` 만큼 기다린 뒤 재시도합니다. |
| 500 | 서버 오류 | 내부 오류 | `request_id` 와 함께 문의합니다. |
| 502 · 503 · 504 | 상류 오류·과부하·시간 초과 | 배포 중이거나 자원 대기 중 | 지수 백오프로 재시도합니다. |

## 자주 만나는 코드

| `error` | 상황 | 조치 |
|---|---|---|
| `INVALID_INPUT` | 요청 형식이 규격에 안 맞음 | 필드 이름·타입·길이 확인 |
| `UNAUTHORIZED` | 인증 실패 | 토큰 갱신 |
| `NOT_FOUND` | 대상 리소스 없음 | ID·프로젝트 확인 |
| `DUPLICATE_NAME` | 같은 범위에 같은 이름이 있음 | 다른 이름으로 |
| `RESOURCE_VALIDATION_FAILED` | 클러스터 자원 부족 (예: GPU) | 요청 자원을 줄이거나 다른 클러스터를 고르거나 기다립니다 |
| `RATE_LIMIT_EXCEEDED` | 호출 한도 초과 | `retry_after` 초 후 재시도 |

레이트 리밋 응답에는 추가 필드가 붙습니다.

```json
{
  "error": "RATE_LIMIT_EXCEEDED",
  "message": "Rate limit exceeded",
  "limit_type": "user",
  "retry_after": 60
}
```

`retry_after` 는 초 단위입니다. 이 값을 무시하고 즉시 재시도하면 한도만 더 태웁니다.

## 재시도해도 되는 것과 안 되는 것

재시도가 의미 있는 것은 **일시적인 실패**뿐입니다.

| 재시도 | 상태 |
|---|---|
| 한다 (지수 백오프) | 429 · 500 · 502 · 503 · 504 |
| 한 번만 (토큰 갱신 후) | 401 |
| 하지 않는다 | 400 · 403 · 404 · 422 |
| 조회 후 재시도 | 409 |

생성·삭제처럼 상태를 바꾸는 요청을 무턱대고 재시도하면 리소스가 중복 생성될 수 있습니다.
재시도 전에 목록을 한 번 조회해 이미 만들어졌는지 확인하세요.
