# 핵심 개념

Metis 의 리소스는 몇 개 안 되는 개념으로 구성되고, 나머지 문서 전체가 이 용어들을
전제로 씁니다. 관계를 먼저 잡아 두면 콘솔 화면도, API 응답도 훨씬 빨리 읽힙니다.

## 프로젝트가 제일 바깥

**프로젝트**는 엔드포인트·볼륨·템플릿을 담는 그릇입니다. 팀이나 용도별로 프로젝트를
나누면 리소스와 사용량이 그 안에서 집계됩니다. 대부분의 API 경로가
`/projects/{project_id}/...` 형태인 이유가 이것입니다 — 거의 모든 것이 어떤 프로젝트에
속해 있습니다.

## 엔드포인트가 실제로 호출하는 단위

**엔드포인트**는 모델 하나를 서빙하는 배포 단위입니다. 엔드포인트를 만들면 전용 주소가
생기고([엔드포인트 URL](/guide/inference/endpoint-url)), 그 주소로 요청을 보내면 실제
추론이 일어납니다. 엔드포인트는 어떤 **클러스터**의 GPU/CPU 자원 위에서 뜨며, 생성할 때
클러스터를 지정하지 않으면 플랫폼이 적절한 클러스터를 고릅니다.

엔드포인트 하나는 다음을 갖습니다.

- **모델** — 어떤 가중치를 서빙할지 (`model`, 필요하면 `model_path`·`hf_token`)
- **워크로드 타입** — 그 모델을 어떤 서버로 띄울지. [워크로드 타입](/guide/workload-types) 참고
- **레플리카 범위** — 아래 참고
- **버전** — 엔드포인트를 수정할 때마다 올라가는 정수. 수정 요청에는 현재 버전을 함께
  보내 낙관적 잠금을 겁니다(다른 곳에서 먼저 바꿨으면 충돌로 거부됩니다)

## 워크로드 = 엔드포인트를 실제로 돌리는 컨테이너 정의

**워크로드**는 워크로드 타입에 맞춰 실제로 뜨는 컨테이너 스펙(이미지, 시작 인자, 포트)을
말합니다. 엔드포인트를 만드는 시점에 `workload_type` 과 `workload_config` 로 함께
지정하므로 평소에는 엔드포인트와 한 몸처럼 다루면 됩니다. VLLM 계열은 `max_model_len`·
`tensor_parallel` 같은 값을, `DOCKER_CUSTOM` 은 이미지 URI 와 포트를 이 설정에 담습니다.

## 볼륨 — 모델·데이터를 담는 영속 저장소

**볼륨**은 엔드포인트가 재시작돼도 남아 있는 저장 공간입니다. 큰 모델 가중치를 매번
다운로드하지 않고 볼륨에 올려 두고 여러 엔드포인트가 재사용하거나, 파인튜닝 산출물을
보관하는 용도로 씁니다.

## 템플릿 — 반복 생성을 줄이는 사전 설정 묶음

**템플릿**은 워크로드 타입·모델·리소스 사이징처럼 엔드포인트를 만들 때마다 반복 입력하는
값을 묶어 둔 것입니다. 같은 모델로 엔드포인트를 자주 새로 만든다면 템플릿에서 시작하는
편이 빠릅니다.

## 클러스터 — 엔드포인트가 실제로 뜨는 물리적 자리

**클러스터**는 GPU/CPU 자원의 실제 풀입니다. 여러 클러스터가 있는 환경이라면 엔드포인트
생성 시 `cluster_id` 로 특정 클러스터를 지정할 수 있고, `VLLM_RBLN`(Rebellions NPU)처럼
특수 하드웨어가 필요한 워크로드는 클러스터 지정이 필수입니다.

## 레플리카와 Scale-to-Zero

엔드포인트는 `min_replica`~`max_replica` 범위 안에서 파드 개수가 자동으로 오르내립니다.
기본값은 `min_replica: 0`, `max_replica: 1` 입니다 — 즉 아무도 안 쓰면 파드가 0개까지
줄어들고(Scale-to-Zero), 요청이 들어오면 그때 다시 뜹니다. 이 동작 때문에 트래픽이 없다가
들어오는 첫 요청은 응답이 느립니다. 대응법은
[콜드 스타트와 Scale-to-Zero](/guide/inference/cold-start) 를 참고하세요.

## 한눈에 관계

```
프로젝트
 ├─ 엔드포인트 (클러스터 위에서 뜬다, 버전 관리)
 │   ├─ 워크로드 (워크로드 타입 + 워크로드 설정)
 │   └─ 레플리카 (min~max, Scale-to-Zero)
 ├─ 볼륨 (엔드포인트가 참조)
 └─ 템플릿 (엔드포인트 생성 시 값 채우기)
```
