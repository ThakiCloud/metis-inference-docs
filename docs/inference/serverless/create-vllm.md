# vLLM 엔드포인트 생성

::: warning 이 환경의 콘솔 메뉴에는 없습니다
이 배포의 사이드바에는 GPU vLLM 항목이 노출되지 않습니다(Docker · CPU vLLM · Rebellions vLLM 만 보입니다). 아래 설명은 기능 자체에 대한 것이고, 플랫폼 API 로는 그대로 쓸 수 있습니다.
설치 환경에 따라 메뉴가 노출되기도 합니다.
:::

GPU 위에서 vLLM 의 OpenAI 호환 서버를 띄웁니다. 텍스트 생성 모델을 서빙할 때 가장 먼저
고려하는 방식입니다. 다른 워크로드 타입과의 차이는 [워크로드 타입](/guide/workload-types)
을 참고하세요.

::: tip 이 환경에서는 사이드바에 노출되지 않습니다
이 화면은 지금 이 환경의 콘솔 사이드바에는 나타나지 않습니다. 사이드바에는 Docker, CPU
vLLM, Rebellions vLLM 세 가지만 보이고 GPU vLLM 항목은 빠져 있습니다. 다만 라우트 자체는
살아 있으므로 주소를 직접 입력해 들어갈 수 있습니다.
:::

## 입력 항목

| 항목 | 필수 | 기본값 | 설명 |
|---|---|---|---|
| 이름 | ✓ | — | DNS-1123 규칙(소문자·숫자·하이픈)을 따르고 63자 이하입니다 |
| 모델 선택 | ✓ | — | 서빙할 모델을 고릅니다 |
| 최소 레플리카 | — | `0` | 트래픽이 없을 때 유지할 최소 파드 수입니다. `0` 이면 Scale-to-Zero 가 적용됩니다 |
| 최대 레플리카 | — | `1` | 트래픽이 몰릴 때 늘어날 수 있는 최대 파드 수입니다. `1` 이상이어야 합니다 |
| 포트 | — | `8000` | 서비스 포트입니다. **8000 으로 고정**되며 바꿀 수 없습니다 |

필수 입력은 이름과 모델뿐입니다. 최소·최대 레플리카는 기본값 그대로 두어도 동작하고,
필요할 때만 조정하면 됩니다. 레플리카 범위와 Scale-to-Zero 가 어떻게 맞물리는지는
[핵심 개념](/guide/concepts) 의 레플리카 항목을 참고하세요.

## 만든 뒤

생성 요청은 접수만 하고 곧바로 돌아옵니다. 상태가 `available` 이 되어야 실제로 호출할 수
있습니다. 진행 상황은 [엔드포인트 조회](/inference/serverless/list) 에서 확인하고, 주소는
배포가 끝난 뒤 [Service URL](/inference/serverless/service-url) 에서 얻습니다.

최소 레플리카를 `0` 으로 두면 트래픽이 없을 때 파드가 내려가고, 다음 요청이 올 때 다시
뜹니다. 이때 첫 요청이 느려지는 이유와 대응법은
[콜드 스타트와 Scale-to-Zero](/guide/inference/cold-start) 에 정리돼 있습니다.
